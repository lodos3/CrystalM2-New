# Structure-aware armour reconstruction

Generated appearances g02–g99 now cover 30 source designs; g02–g12 retain their prior recipe identity and g13–g99 are reassigned. g01 and ordinary equipped armour are unchanged. All clients must have matching CArmour/01.Lib–30.Lib to see the same catalogue. Missing or incompatible files use the existing renderer failure/fallback path. The supplied 12–15 archives have 1616 frames; 16–29 have 8080; 30 has 6464. The first 1616 frames of every supplied source and the naked reference (50,096 frames total) were independently decoded with exact byte-length checks. Six representative poses per archive across both body banks were visually inspected. The additional animation banks are not supported by the classic renderer. The source-wide model learns from 64 fixed frames, both body banks and all eight facings. Existing head/hand extraction runs before all analysis. The material map has zero coverage at identified skin or transparent pixels.

Each source frame now stores four continuous palette memberships. Two edge-aware regularization passes use spatial neighbours and original RGB distances, without crossing transparent/skin pixels. Signed local luminance contrast estimates raised edges and recesses; repeated offset comparisons and local variance estimate texture. This is an approximate 2D method inspired by palette decomposition and patch comparison, not an implementation of the RGBXY convex-hull solver, PatchMatch, an intrinsic-image neural network, or recovered physical normal maps. No synthetic geometry or random texture is introduced.

Nine finish recipes apply weighted reference-palette soft-light/colour blending, selective screen polishing, multiply recess tint and restrained native texture contrast. Runtime uploads one combined surface, protected skin and a structure texture (BGRA: texture/recess/ridge/coverage). The shader samples the structure texture at native texels and applies a low-energy animated screen reflection, never a whole-sprite additive overlay. All profiles have their own finish and reflection strengths. Existing greyscale and effects-disable settings are respected. Original dimensions, offsets and alpha are retained.

A 24 MiB bounded source-frame analysis LRU shares material maps across variants; the existing 32 MiB GPU cache now stores at most three textures per generated frame. First access still computes a source-wide model and per-frame maps on the CPU. No disk pre-bake or cross-frame optical-flow propagation is implemented. Fixed source-wide memberships and deterministic local features reduce switching, but actual animation coherence needs visual verification.

The existing --live/--live-one export commands now write HeadHands, Surface, Layer0–3 (disjoint ownership views of the weighted composite), and Structure LIBs. Structure is a diagnostic data map, not a drawable armour. The authoring command --material-source <Data> <Art/CArmour> <output> <source 1–30> <finish 0–8> can export any of the 270 source/finish combinations without changing the fixed 98-ID runtime catalogue. Only the inspected classic prefixes are accepted; this does not claim every animation or anatomy mask is visually verified. Use a new destination folder. Source LIBs are read-only.

Tests cover deterministic extraction, normalized soft weights, original relief, protected pixels, alpha, flat-region rejection and all 98 appearance IDs using test-only synthetic fixtures. Actual source libraries and Windows D3D11 compilation must be validated separately.
